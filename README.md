# 4DOWON · ESP32 와이파이 설정 실험

T-Display가 설정용 와이파이를 열고, 휴대폰의 웹 페이지에서 집·작업실 와이파이를 저장하는 첫 테스트입니다. 인터넷에 연결되면 보드 화면에 한국 시간 시계가 표시됩니다.

**대상 보드**는 기존 **LILYGO / TTGO T-Display 1.14인치 ESP32, 4MB 또는 16MB**입니다. CH9102F 버전으로 진행했던 플립시계용 보드에 맞췄습니다. T-Display-S3는 핀과 화면이 달라 별도 설정이 필요합니다.

## 준비물

- T-Display 1개
- 데이터 전송이 가능한 USB-C 케이블과 Mac/PC
- 휴대폰과 2.4GHz 와이파이

이번 실험에는 핀헤더 납땜, Buddy, 모터, 모터 전원이 필요하지 않습니다. T-Display에 USB만 연결합니다. 업로드하면 보드에 들어 있던 기존 프로그램은 이 테스트 프로그램으로 교체됩니다.

## 처음 한 번 코드 올리기 — VS Code + PlatformIO

1. [VS Code](https://code.visualstudio.com/)를 설치하고, 확장 탭에서 **PlatformIO IDE**를 설치합니다. 설치 후 안내에 따라 VS Code를 다시 엽니다.
2. 저장소를 다운로드합니다. GitHub의 **Code → Download ZIP**으로 받아 압축을 풀거나, 터미널에서 아래 명령을 실행합니다.

   ```sh
   git clone https://github.com/threedowon/esp-wifi-setup.git
   ```

3. VS Code에서 **File → Open Folder**로 `platformio.ini`가 있는 `esp-wifi-setup` 폴더를 엽니다.
4. T-Display를 데이터 USB 케이블로 컴퓨터에 연결합니다.
5. 왼쪽 PlatformIO 아이콘 → **PROJECT TASKS → t-display → General → Build**를 누릅니다. 첫 실행은 보드 도구와 라이브러리를 내려받느라 시간이 걸립니다.
6. 같은 위치에서 **Upload**를 누릅니다. 업로드 성공 후 보드가 재부팅됩니다. 변화가 없으면 보드의 RST를 한 번 누릅니다.
7. 보드에 `4DOWON / WI-FI SETUP`과 접속 정보가 나오면 아래 순서로 진행합니다.

설치된 PlatformIO CLI를 쓰는 경우, 저장소 폴더에서 다음 명령으로 빌드·업로드합니다.

```sh
pio run
pio run --target upload
pio device monitor --baud 115200
```

여러 보드가 연결되어 있으면 `pio device list`로 포트를 확인하고 `pio run -t upload --upload-port /dev/cu.실제포트이름`처럼 지정합니다.

## 휴대폰으로 설정하기

1. 휴대폰의 **설정 → Wi-Fi**에서 보드 화면에 나온 `4DOWON-Setup-XXXXXX`를 선택합니다. 끝 여섯 자리는 기기마다 다릅니다.
2. 보드 화면의 **PW** 옆 12자리 비밀번호를 입력합니다. 이 비밀번호는 설정용 와이파이 비밀번호입니다.
3. 휴대폰에 “인터넷 연결 없음”이 나와도 **연결 유지**를 선택합니다. 설정 페이지를 제공하는 시계에 연결된 상태입니다.
4. 설정 페이지가 자동으로 뜨지 않으면 Safari/Chrome 주소창에 **`http://192.168.4.1`**을 직접 입력합니다. 검색창 대신 주소창을 사용하고 `http://`를 포함합니다.
5. **주변 와이파이 찾기**를 눌러 집·작업실 와이파이를 선택하고 **그 공유기의 비밀번호**를 입력합니다. 숨긴 SSID는 직접 입력할 수 있습니다.
6. **연결하고 저장하기**를 누릅니다. 최대 약 25초 기다립니다. AP와 집 와이파이의 채널이 바뀌면서 휴대폰 연결이 잠깐 끊길 수 있습니다. 다시 보드의 설정용 와이파이에 접속해 같은 주소를 열면 결과를 볼 수 있습니다.
7. 연결 성공 후 원하는 **12/24시간 형식과 화면 밝기**를 골라 **화면 설정 저장**을 누릅니다.
8. **설정 마치고 시계 보기**를 누르면 약 3초 뒤 설정용 와이파이가 꺼지고 보드에 시계가 표시됩니다. 휴대폰을 평소 와이파이에 다시 연결합니다.

집 와이파이에 연결되어도 인터넷이 막혀 있으면 시간 동기화는 기다리는 상태로 남습니다. 페이지의 시계는 보드에서 받은 시간을 표시합니다. 초기 동기화 전에는 `--:--`를 보여줍니다.

## 다음부터는 USB 전원만

저장한 와이파이로 자동 연결합니다. 비밀번호를 코드에 적을 필요가 없으며, 전원을 꺼도 연결 정보와 화면 설정이 남습니다. 전원을 완전히 끈 뒤 다시 켜면 정확한 현재 시간을 얻기 위해 인터넷 동기화가 필요합니다.

**와이파이를 바꾸려면 IO35 버튼을 3초간 누릅니다.** 기존 T-Display의 화면이 있는 면에서 USB 포트를 아래로 두면 오른쪽 버튼입니다. PCB의 `35`/`IO35` 표기를 함께 확인하세요. 왼쪽 GPIO0 버튼과 옆면 RST 버튼은 별개입니다.

- 최초 실행 때 저장 정보가 없으면 설정용 와이파이를 바로 엽니다.
- 저장한 와이파이 연결에 약 25초 동안 실패하면 설정용 와이파이를 엽니다.
- 정상 사용 중 연결이 끊기면 자동 재연결을 시도하고, 약 30초 이상 끊긴 상태가 이어지면 설정용 와이파이도 엽니다.
- 새 와이파이는 연결과 IP 할당에 성공한 뒤 저장합니다. 실패하면 이전 저장 정보를 유지하며 전원을 다시 켰을 때 이전 정보로 연결합니다.
- 정상 연결 후 페이지 접근이 10분간 없으면 설정용 와이파이를 닫습니다. 페이지를 열어둔 동안에는 상태 확인 요청이 이어져 설정 모드가 유지됩니다.

## 잘 안 될 때

| 상황 | 확인할 것 |
| --- | --- |
| 업로드 포트가 안 보여요 | 충전 전용 케이블인지 확인하고 다른 데이터 케이블로 연결합니다. CH9102 드라이버가 필요한 경우 [설치 안내](https://learn.adafruit.com/how-to-install-drivers-for-wch-usb-to-serial-chips-ch9102f-ch9102/mac-driver-installation)를 확인합니다. |
| Upload가 `Connecting...`에서 멈춰요 | GPIO0 버튼을 누른 채 RST를 짧게 누릅니다. 업로드가 시작되면 GPIO0에서 손을 뗍니다. 업로드 후 RST를 한 번 누릅니다. |
| 보드 화면이 안 나와요 | 원본 1.14인치 T-Display인지 확인하고 RST를 누릅니다. Serial Monitor(115200)에서 설정용 SSID와 비밀번호도 확인할 수 있습니다. |
| 페이지가 자동으로 안 열려요 | 설정용 와이파이에 연결된 상태에서 `http://192.168.4.1`을 직접 엽니다. VPN을 잠시 끄거나 인터넷 없는 Wi-Fi 연결 유지를 선택합니다. |
| 집 와이파이가 안 보여요 | ESP32가 지원하는 2.4GHz 네트워크인지 확인합니다. 검색은 최대 20개의 서로 다른 이름을 보여주며 직접 입력도 가능합니다. |
| 비밀번호가 맞는데 실패해요 | 공유기 신호와 접속 제한을 확인합니다. 이 버전은 일반 가정용 비밀번호 방식 또는 개방형 네트워크를 대상으로 합니다. 회사의 사용자 계정 로그인(Enterprise)이나 브라우저 추가 로그인이 필요한 네트워크는 별도 구현이 필요합니다. |
| 보드 설정을 완전히 지우고 싶어요 | `pio run -t erase` 후 `pio run -t upload`를 실행합니다. 모든 플래시 내용을 지우므로 펌웨어, 저장한 와이파이, 화면 설정도 초기화됩니다. |

## 코드 구성

| 파일 | 역할 |
| --- | --- |
| `src/main.cpp` | AP·DNS·HTTP 서버, 와이파이 연결과 저장, 버튼, 시간 동기화, LCD |
| `web/index.html` | 인터넷 없이 열리는 한국어 설정 화면. 외부 폰트·CDN을 사용하지 않음 |
| `scripts/embed_web.py` | 빌드할 때 HTML을 펌웨어에 포함. 웹 파일을 별도 업로드할 필요 없음 |
| `platformio.ini` | 원본 T-Display 핀 배치, 도구와 라이브러리 버전 고정 |

네트워크는 ESP32 내장 `WiFi`, `WebServer`, `DNSServer`로 구현했습니다. WiFiManager를 추가하는 방식 대신 직접 작성한 페이지를 내장하여 문구와 디자인을 수정하기 쉽게 했습니다. 시간대는 한국(UTC+9)으로 고정되어 있습니다.

설정 HTTP API는 설정용 AP를 통해 들어온 요청만 받습니다. 페이지마다 설정 세션 토큰을 사용하며 공유기 비밀번호를 응답이나 로그로 내보내지 않습니다. 연결 정보는 보드의 Preferences/NVS에 저장되고, 기본 빌드에서 플래시 암호화는 적용하지 않습니다. 보드 화면과 USB 시리얼에는 설정용 AP의 비밀번호만 표시합니다.

## 플립시계와 연결할 때

현재 프로젝트는 T-Display 단독 네트워크·화면 실험입니다. 다음 단계에서 Scott splitflap 펌웨어의 모터 처리 루프와 합치며, Wi-Fi 설정이 진행되는 동안에도 모터 처리와 원점 감지가 동작하도록 통합합니다. 지금 코드에는 모터 구동이 포함되어 있지 않습니다.

## 검증 범위

개발 중 페이지 동작을 검사하려면 Node.js 18 이상에서 `npm install --no-save --package-lock=false jsdom@26.1.0`을 실행한 뒤 `node tests/portal.cjs`를 실행합니다. DOM과 모의 API로 입력·검색·연결 실패 후 재시도·시계 설정·완료 동작을 검사합니다. 실제 브라우저의 화면 배치와 보드의 무선 통신은 별도 확인 대상입니다.

컴파일과 DOM의 모의 API 테스트는 소프트웨어 검증입니다. 실제 보드의 화면, 버튼, AP 접속, 공유기 연결, 전원 재연결은 아래 항목으로 별도 확인합니다.

- [ ] 최초 업로드 후 SSID와 PW가 화면에 표시된다.
- [ ] 휴대폰 연결 후 설정 페이지가 열린다.
- [ ] 틀린 공유기 비밀번호로 실패한 뒤 다시 입력할 수 있다.
- [ ] 올바른 정보로 연결되고 시간이 동기화된다.
- [ ] 설정을 마치면 보드에 시계가 표시된다.
- [ ] USB를 뺐다 꽂아도 와이파이와 밝기·형식이 유지된다.
- [ ] IO35를 3초 누르면 다시 설정할 수 있다.
